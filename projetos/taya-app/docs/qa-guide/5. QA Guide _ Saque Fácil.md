# QA Guide — Jornada Saque Fácil
**seutudo. · Taya Tech · Confidencial**
Versão 1.0 — Maio 2026

---

## Visão Geral da Jornada

A jornada do Saque Fácil converte o limite disponível de um cartão de crédito em dinheiro na conta do usuário. É composta por **5 etapas sequenciais** com stepper visual.

```
[1. Educacional] → [2. Simulação] → [3. Dados Complementares] → [4. Cartão + Verificação] → [5. Confirmação / Sucesso]
```

Rota: `/saque-facil`
Analytics: `trackStep()` em todas as subtelas

---

## Como usar este guia

Cada seção abaixo cobre uma etapa da jornada. Para cada etapa:
- **Caso de sucesso (Happy Path)**: entrada válida, comportamento esperado, resultado correto
- **Casos alternativos (Forks)**: entradas inválidas ou condições de exceção, com o comportamento esperado do app em cada caso

Rode sempre o **Happy Path completo primeiro** antes de testar forks isolados.

## Etapa 1 — Tela Educacional

### Objetivo
Apresentar o produto ao usuário e obter consentimento para prosseguir.

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 1.1 | Usuário acessa `/saque-facil` | Tela educacional exibida com explicação do produto |
| 1.2 | Usuário lê o conteúdo e clica em "Continuar" ou CTA equivalente | Avança para Etapa 2 (Simulação) |
| 1.3 | Stepper mostra etapa 1 ativa | Indicador visual correto no topo |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F1.1 | Usuário não autenticado acessa a rota diretamente | Acessar `/saque-facil` sem sessão ativa | Redirecionar para `/acesso` (login) |
| F1.2 | Usuário clica em voltar na tela educacional | Pressionar back do browser ou botão voltar | Retornar para `/painel` sem perder sessão |

## Etapa 2 — Simulação

### Objetivo
Usuário define o valor que deseja receber e a quantidade de parcelas. O app exibe o limite disponível no cartão e o custo total.

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 2.1 | Tela exibe o limite disponível do cartão | Valor mockado/real exibido corretamente |
| 2.2 | Usuário ajusta o slider de valor | Valor e parcelas atualizam em tempo real |
| 2.3 | Usuário seleciona número de parcelas | Resumo financeiro atualiza (total, taxa, parcela mensal) |
| 2.4 | Usuário clica em "Continuar" | Avança para Etapa 3 |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F2.1 | Valor solicitado acima do limite disponível | Forçar valor acima do limite via dev tools | Slider bloqueado no máximo; mensagem "Valor máximo disponível: R$ X" |
| F2.2 | Valor solicitado abaixo do mínimo permitido | Arrastar slider para o mínimo e tentar avançar | Botão desabilitado ou mensagem de valor mínimo (ex: "Mínimo R$ 300") |
| F2.3 | Usuário não seleciona parcelas | Tentar avançar sem selecionar número de parcelas | Validação inline; botão "Continuar" desabilitado |
| F2.4 | Limite do cartão zerado ou indisponível | Simular retorno de limite = 0 | Tela de bloqueio com mensagem amigável + CTA para outros produtos (cross-sell) |

## Etapa 3 — Dados Complementares

### Subetapas: Dados Pessoais → Endereço (ViaCEP) → Dados Bancários

### 3A — Dados Pessoais

#### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 3A.1 | Usuário preenche RG (número + órgão emissor) | Campo aceita; formatação automática se aplicável |
| 3A.2 | Usuário preenche data de nascimento | Campo aceita formato DD/MM/AAAA |

| 3A.5 | Usuário seleciona sexo | Opções disponíveis |
| 3A.6 | Clica em "Avançar" | Avança para subetapa de endereço |

#### Forks — RG
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F3A.1 | **RG inválido** — formato incorreto | Digitar letras onde só há números, ou sequência inválida (ex: "000000000") | Mensagem de erro inline: "RG inválido. Verifique o número e tente novamente." |
| F3A.2 | RG com caracteres especiais | Colar string com `!@#$%` | Campo rejeita entrada ou limpa automaticamente |
| F3A.3 | RG em branco | Tentar avançar sem preencher | Validação bloqueia; campo destacado em vermelho |
| F3A.4 | RG já utilizado em outra conta | Simular conflito via mock da API | Mensagem: "Esse documento já está associado a outra conta. Entre em contato com o suporte." |

#### Forks — Data de Nascimento
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F3B.1 | **Data de nascimento inválida** — data inexistente | Digitar 31/02/2000 | Mensagem: "Data inválida. Verifique o dia e mês informados." |
| F3B.2 | Usuário menor de 18 anos | Digitar data que resulte em idade < 18 | Mensagem: "É necessário ter 18 anos ou mais para contratar." Botão bloqueado. |
| F3B.3 | Data no futuro | Digitar data posterior a hoje | Mensagem: "Data de nascimento não pode ser futura." |
| F3B.4 | Data com mais de 100 anos atrás | Digitar data com ano < (ano atual - 100) | Validação de razoabilidade; mensagem de erro genérica |
| F3B.5 | Campo em branco | Tentar avançar sem preencher | Validação bloqueia; campo destacado |

#### Forks — Outros Campos Pessoais
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F3C.1 | Renda zerada ou negativa | Digitar 0 ou valor negativo | Mensagem: "Informe uma renda válida." |
| F3C.2 | Estado civil não selecionado | Tentar avançar sem selecionar | Validação bloqueia |

### 4C — Verificação de Titularidade (Unico IDPay / IDCloud)

#### Contexto
O sistema verifica que quem está contratando é o titular do cartão informado, via selfie com prova de vida.

#### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 4C.1 | Tela explica que é necessária uma selfie do titular | Usuário lê e clica em "Sou o titular" |
| 4C.2 | SDK Unico abre câmera | Câmera funcional; interface do Unico carrega |
| 4C.3 | Usuário realiza selfie com prova de vida | Selfie capturada com sucesso |
| 4C.4 | Unico retorna aprovação | App avança para Etapa 5 (Confirmação) |

#### Forks — Titularidade
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F4C.1 | **Titularidade inválida** — selfie não corresponde ao titular | Simular retorno negativo do Unico | Mensagem: "Não foi possível confirmar a titularidade do cartão. Verifique se você é o titular ou tente outro cartão." + opções: tentar novamente ou cancelar |
| F4C.2 | Usuário não é o titular e declara isso | Clicar em opção "Não sou o titular" (se disponível) | Fluxo bloqueado: "O Saque Fácil só pode ser contratado pelo titular do cartão." |
| F4C.3 | Câmera sem permissão | Negar permissão de câmera no browser/app | Mensagem: "Precisamos de acesso à câmera para verificar sua identidade. Ative nas configurações e tente novamente." |
| F4C.4 | SDK Unico timeout ou erro | Simular falha de rede ou timeout do SDK | Mensagem: "Falha na verificação de identidade. Tente novamente." + botão de retry |
| F4C.5 | Prova de vida não detectada (foto estática) | Tentar usar foto impressa ou tela de celular | SDK retorna erro de liveness; mensagem de instrução para selfie real |
| F4C.6 | Máximo de tentativas atingido | Falhar 3x consecutivas na verificação | Bloqueio temporário: "Número máximo de tentativas atingido. Tente novamente em X minutos." ou "Entre em contato com o suporte." |

## Checklist de Regressão (rodar a cada deploy)

- [ ] Happy Path completo do início ao sucesso
- [ ] Validação de RG inválido (F3A.1)
- [ ] Validação de data de nascimento inválida (F3B.1) e menor de idade (F3B.2)
- [ ] CEP inexistente com fallback manual (F3D.1 e F3D.3)
- [ ] Cartão com número inválido (F4A.1) e expirado (F4A.2)
- [ ] Falha de titularidade no Unico (F4C.1)
- [ ] Elegibilidade reprovada (F5A.1)
- [ ] Toggle de privacidade mascarando dados sensíveis (FT.5)
- [ ] Comportamento de back em todas as etapas (FT.3)
- [ ] Sessão expirada redirecionando corretamente (FT.2)
