# QA Guide — Login e Autenticação
**seutudo. · Taya Tech · Confidencial**
Versão 1.0 — Maio 2026

---

## Visão Geral da Jornada

O fluxo de autenticação permite que usuários já cadastrados acessem o app com CPF + senha, seguido de verificação por código OTP via canal escolhido pelo usuário.

```
[Boas-vindas] → [1. CPF + Senha] → [2. Escolha do canal OTP] → [3. Inserir código OTP] → [Home]
```

Rota: `/acesso`
Acesso: apenas usuários não autenticados

---

## Como usar este guia

Cada seção cobre uma etapa do fluxo. Para cada etapa:
- **Caso de sucesso (Happy Path)**: entrada válida, comportamento esperado, resultado correto
- **Casos alternativos (Forks)**: entradas inválidas ou condições de exceção, com o comportamento esperado do app em cada caso

Rode sempre o **Happy Path completo primeiro** antes de testar forks isolados.

## Etapa 1 — CPF + Senha

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 1.1 | Campo de CPF com máscara `000.000.000-00` | Máscara aplicada ao digitar |
| 1.2 | Usuário digita CPF válido com 11 dígitos | Botão "Entrar" habilitado quando senha também preenchida |
| 1.3 | Campo de senha com toggle de visibilidade | `ph-eye` / `ph-eye-slash` alterna exibição |
| 1.4 | Usuário digita senha de 6 dígitos | Campo aceita apenas números |
| 1.5 | Botão "Entrar" ativo com CPF completo e senha >= 6 dígitos | Botão habilitado |
| 1.6 | Usuário clica em "Entrar" | Avança para Etapa 2 |
| 1.7 | Link "Criar minha conta" visível | Clique navega para `/cadastro` |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F1.1 | CPF inválido (algoritmo) | Digitar `111.111.111-11` | Mensagem: "CPF inválido. Verifique o número." Botão desabilitado. |
| F1.2 | CPF com menos de 11 dígitos | Digitar número incompleto | Botão desabilitado |
| F1.3 | Senha com menos de 6 dígitos | Digitar 5 números | Botão desabilitado |
| F1.4 | CPF não cadastrado | Simular retorno 404 da API | Mensagem: "CPF não encontrado. Verifique ou crie sua conta." + CTA para `/cadastro` |
| F1.5 | Senha incorreta | Simular retorno 401 da API | Mensagem: "Senha incorreta. Tente novamente." Campo de senha limpo. |
| F1.6 | Conta bloqueada por excesso de tentativas | Simular 5 tentativas falhas | Mensagem: "Conta temporariamente bloqueada. Tente novamente em X minutos." Botão com countdown. |
| F1.7 | Campos em branco | Tentar avançar | Botão desabilitado |
| F1.8 | Link "Esqueci minha senha" | Clicar no link | Navega para fluxo de recuperação (a implementar) ou modal informativo |

## Etapa 2 — Escolha do Canal OTP

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 2.1 | Tela exibe 3 opções de canal | WhatsApp (recomendado, pré-selecionado), E-mail, SMS |

| 2.3 | Badge "Recomendado" visível no WhatsApp | Exibido como destaque |
| 2.4 | Usuário seleciona canal alternativo | Card selecionado recebe estado visual |
| 2.5 | Botão "Enviar código" sempre ativo | Canal já pré-selecionado |
| 2.6 | Usuário clica em "Enviar código" | Avança para Etapa 3 |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F2.1 | Usuário pressiona voltar | Botão voltar ou back do browser | Retorna para Etapa 1 sem limpar campos |
| F2.2 | Falha no envio do OTP via WhatsApp | Simular erro de envio | Mensagem: "Não conseguimos enviar o código. Tente outro canal ou tente novamente." |
| F2.3 | Falha no envio via e-mail | Simular erro de envio | Mensagem equivalente com sugestão de canal alternativo |
| F2.4 | Número inválido para SMS | Simular número de telefone inválido no cadastro | Mensagem: "Não foi possível enviar SMS. Tente por WhatsApp ou e-mail." |

## Etapa 3 — Inserir Código OTP

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 3.1 | Ícone do canal selecionado em círculo laranja | Canal correto indicado visualmente |
| 3.2 | Subtítulo dinâmico por canal | WhatsApp / E-mail / SMS com texto correspondente |
| 3.3 | Componente InputOTP com 6 slots | Foco no primeiro slot ao carregar |
| 3.4 | Toast Sonner após 1,5s | "seutudo. — Seu código de verificação chegou." |
| 3.5 | Usuário digita 6 dígitos | Foco avança automaticamente entre slots |
| 3.6 | Botão "Confirmar" ativo com 6 dígitos | Habilitado somente com OTP completo |
| 3.7 | Usuário clica em "Confirmar" | Navega para `/painel` |
| 3.8 | Countdown de reenvio visível | "Reenviar código em X:XX" |
| 3.9 | Countdown chega a 0:00 | Link "Não recebi o código — reenviar" habilitado |
| 3.10 | Usuário clica em reenviar | Novo código enviado; countdown reinicia |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F3.1 | OTP com menos de 6 dígitos | Preencher parcialmente | Botão desabilitado |
| F3.2 | Código inválido | Simular retorno 401 | Mensagem: "Código inválido. Verifique e tente novamente." Slots limpos. |
| F3.3 | Código expirado | Simular token expirado | Mensagem: "Este código expirou. Solicite um novo." Reenvio habilitado. |
| F3.4 | Máximo de tentativas | Errar código 3x | Bloqueio: "Número máximo de tentativas atingido. Solicite um novo código." |
| F3.5 | Voltar na Etapa 3 | Botão voltar | Retorna para Etapa 2; código anterior invalidado |
| F3.6 | Reenvio antes do countdown | Clicar antes do zero | Link desabilitado até countdown chegar a 0:00 |
| F3.7 | Usuário cola código do clipboard | Colar string de 6 dígitos | Código preenchido automaticamente; botão habilitado |
| F3.8 | Usuário cola código com letras | Colar "abc123" | Apenas dígitos aceitos; letras ignoradas ou rejeitadas |

## Checklist de Regressão (rodar a cada deploy)

- [ ] Happy Path completo: boas-vindas → CPF + senha → canal OTP → código → home
- [ ] Redirecionamento de usuário autenticado para `/painel` (FBV.1)
- [ ] CPF inválido bloqueia avanço (F1.1)
- [ ] Senha com menos de 6 dígitos desabilita botão (F1.3)
- [ ] WhatsApp pré-selecionado por padrão na Etapa 2
- [ ] Toast Sonner disparado 1,5s após entrar na Etapa 3
- [ ] Foco automático entre slots do OTP
- [ ] Botão "Confirmar" desabilitado com OTP incompleto (F3.1)
- [ ] Countdown funcional; reenvio habilitado somente após zero (F3.6)
- [ ] Redirect para rota de origem após login (FPA.1)
- [ ] Layout desktop com foto à esquerda e formulário à direita (FT.4)
- [ ] Back na Etapa 2 preserva campos da Etapa 1 (F2.1)
- [ ] Back na Etapa 3 retorna para Etapa 2 (F3.5)
