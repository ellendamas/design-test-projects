# QA Guide — Jornada de Onboarding
**seutudo. · Taya Tech · Confidencial**
Versão 1.0 — Maio 2026

---

## Visão Geral da Jornada

O onboarding cadastra novos usuários no app e os direciona para a home personalizada. É composto por **5 passos sequenciais** com barra de progresso, precedidos por splash screen e tela de boas-vindas.

```
[Splash] → [Boas-vindas] → [1. Dados básicos] → [2. CPF] → [3. Produtos] → [4. Senha] → [5. Biometria] → [Sucesso] → [Home]
```

Rota principal: `/cadastro`
Rotas auxiliares: `/` (splash), `/boas-vindas`
Analytics: `trackStep()` em cada subtela

---

## Como usar este guia

Cada seção cobre uma etapa da jornada. Para cada etapa:
- **Caso de sucesso (Happy Path)**: entrada válida, comportamento esperado, resultado correto
- **Casos alternativos (Forks)**: entradas inválidas ou condições de exceção, com o comportamento esperado do app em cada caso

Rode sempre o **Happy Path completo primeiro** antes de testar forks isolados.

## Passo 1 — Dados Básicos

### Objetivo
Coletar nome completo, e-mail e telefone do usuário.

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 1.1 | Tela exibe campos: nome, e-mail, telefone | Formulário renderizado; barra de progresso em 20% |
| 1.2 | Usuário preenche nome completo (mín. 3 chars) | Campo aceita; sem formatação automática |
| 1.3 | Usuário preenche e-mail válido | Campo aceita; sem validação em tempo real |
| 1.4 | Usuário preenche telefone com DDD | Máscara `(00) 00000-0000` aplicada automaticamente |
| 1.5 | Botão "Continuar" ativo com todos os campos válidos | Botão habilitado |
| 1.6 | Usuário clica em "Continuar" | Avança para Passo 2 |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F1.1 | Nome com menos de 3 caracteres | Digitar "Jo" e tentar avançar | Botão desabilitado ou mensagem: "Informe seu nome completo." |
| F1.2 | E-mail sem @ ou domínio | Digitar "emailsemaroba" | Botão desabilitado; validação inline ao perder foco |
| F1.3 | Telefone com menos de 10 dígitos | Digitar número incompleto | Botão desabilitado |
| F1.4 | Campos em branco | Tentar avançar sem preencher | Validação bloqueia; campos obrigatórios destacados |
| F1.5 | E-mail já cadastrado | Simular retorno de conflito da API | Mensagem: "Este e-mail já está em uso. Tente fazer login ou use outro e-mail." |
| F1.6 | Telefone já cadastrado | Simular retorno de conflito | Mensagem amigável com CTA para login |

## Passo 2 — CPF

### Objetivo
Coletar e validar o CPF do usuário.

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| 2.1 | Tela exibe campo de CPF com strip de segurança LGPD | Formulário renderizado; barra de progresso em 40% |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| F2.1 | CPF com dígitos inválidos (algoritmo) | Digitar `111.111.111-11` | Mensagem: "CPF inválido. Verifique o número e tente novamente." |
| F2.2 | CPF em branco | Tentar avançar sem preencher | Botão desabilitado |

| F2.5 | CPF de pessoa menor de idade | Validação com base em data de nascimento futura (se coletada antes) | Se validação cruzada disponível: "Não é possível cadastrar menores de 18 anos." |

| ID | Cenário | Comportamento esperado |
|----|---------|----------------------|
| FT.1 | Perda de conexão durante o cadastro | Mensagem: "Sem conexão. Verifique sua internet e tente novamente." Dados do passo atual preservados. |

| FT.4 | Acesso via desktop | Layout com sidebar oculta; formulários centralizados `max-w-[480px]`; comportamento idêntico ao mobile |

## Checklist de Regressão (rodar a cada deploy)

- [ ] Happy Path completo: splash → boas-vindas → 5 passos → sucesso → home
- [ ] Redirecionamento de usuário autenticado para `/painel`
- [ ] Validação de e-mail inválido (F1.2)
- [ ] Validação de CPF inválido (F2.1)
- [ ] CPF já cadastrado com CTA para login (F2.4)
- [ ] Seleção de produtos: ao menos 1 obrigatório (F3.1)
- [ ] Senha com menos de 6 dígitos bloqueada (F4.1)
- [ ] Botão "Agora não" na biometria funciona (F5.2)
- [ ] Back em todos os passos sem perda de dados (FT.2)
- [ ] Persistência do `seutudo_user` em localStorage após sucesso
- [ ] Layout desktop centralizado sem sidebar

### 22/07/2026 — Biometria pós-cadastro

> Detalha o item "Sheet de biometria" já citado no fluxo acima — biometria é mock, sem integração real com WebAuthn/FaceID/TouchID (preferência só salva em localStorage).

**Sheet de biometria adicionada após o step 5 (necessidades):**
- Ao concluir o step de necessidades, abre um Dialog (desktop) ou Drawer (mobile) perguntando se o usuário quer ativar biometria — título "Entre mais rápido com biometria".
- "Ativar biometria" → salva `podeja_biometria_ativa = "true"` no localStorage → navega para `/painel`.
- "Agora não" → salva `podeja_biometria_ativa = "false"` → navega para `/painel`.

**Atalho de biometria no login (`/acesso`):**
- Quando `podeja_biometria_ativa === "true"`, ao chegar no step 1 do login abre automaticamente um overlay (Dialog/Drawer) "Entrar com biometria", com botão "Usar biometria" e opção "Entrar com CPF e senha" para pular.
- "Usar biometria" simula 1s de verificação e navega direto para `/painel` (sem digitar senha).
- **Atenção:** isso é um overlay que aparece por cima do formulário de login, não um botão inline com separador dentro do próprio formulário.

**Chave de localStorage:**
- `podeja_biometria_ativa`: `"true"` | `"false"`.
