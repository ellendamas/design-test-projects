# QA Guide — Fluxo "Esqueci minha senha"
**seutudo. · Taya Tech · Confidencial**
Versão 1.0 — Maio 2026

---

## Visão Geral do Fluxo

Fluxo de recuperação de senha acessado pelo link "Esqueci minha senha" na tela de login (/acesso). Composto por 4 etapas sequenciais com barra de progresso.

```
[1. CPF] → [2. Canal] → [3. OTP] → [4. Nova senha] → /acesso
```

Rotas:
- `/recuperar-senha` — Etapa 1
- `/recuperar-senha/canal` — Etapa 2
- `/recuperar-senha/otp` — Etapa 3
- `/recuperar-senha/nova-senha` — Etapa 4

---

## Como usar este guia

Para cada etapa: rode o **Happy Path primeiro**, depois teste os forks isoladamente. O código OTP válido simulado é **123456**. O código expirado simulado é **000000**. O CPF não cadastrado simulado é **000.000.000-00**.

---

## Etapa RS1 — Informe seu CPF

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| RS1.1 | Usuário clica em "Esqueci minha senha" na tela de login | Navega para /recuperar-senha; barra de progresso em 25% |
| RS1.2 | Usuário digita CPF válido com máscara | Campo aceita; botão "Continuar" habilita |
| RS1.3 | Clica em "Continuar" | Navega para /recuperar-senha/canal |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FRS1.1 | CPF em branco | Tentar avançar sem preencher | Botão desabilitado |
| FRS1.2 | CPF com formato inválido | Digitar menos de 11 dígitos | Erro inline: "CPF inválido. Verifique e tente novamente." |
| FRS1.3 | CPF não cadastrado | Digitar 000.000.000-00 | Erro inline: "CPF não encontrado. Verifique ou faça seu cadastro." |
| FRS1.4 | Usuário clica em voltar | Pressionar voltar ou seta do header | Retorna para /acesso sem limpar campos |
| FRS1.5 | Acesso direto à etapa 2, 3 ou 4 sem passar pela etapa 1 | Acessar URL diretamente no browser | Redirecionar para /recuperar-senha |

## Etapa RS2 — Escolha do Canal

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| RS2.1 | Tela exibe 3 cards: WhatsApp, SMS, Email com dados mascarados | Cards exibidos corretamente |
| RS2.2 | Usuário seleciona um canal | Card selecionado com borda laranja + fundo claro |
| RS2.3 | Clica em "Enviar código" | Toast "Código enviado via [canal]!"; navega para /recuperar-senha/otp |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FRS2.1 | Nenhum canal selecionado | Tentar avançar sem selecionar | Botão "Enviar código" desabilitado |
| FRS2.2 | Falha no envio do código (API offline) | Simular erro de envio | Mensagem: "Não conseguimos enviar o código agora. Tente novamente." |
| FRS2.3 | Usuário troca de canal após selecionar | Clicar em outro card | Seleção muda; apenas um canal ativo por vez |

## Etapa RS3 — Código OTP

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| RS3.1 | Tela exibe 6 inputs + subtítulo com canal escolhido | Exibição correta e dinâmica conforme canal |
| RS3.2 | Usuário digita o código | Auto-foco avança campo a campo |
| RS3.3 | Usuário cola o código completo | Todos os 6 campos preenchidos automaticamente |
| RS3.4 | Digita 123456 e clica "Verificar" | Navega para /recuperar-senha/nova-senha |
| RS3.5 | Contador chega a 0 | Link "Reenviar código" aparece |
| RS3.6 | Clica em "Reenviar código" | Contador reinicia 60s + toast "Código reenviado!" |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FRS3.1 | Código incorreto | Digitar qualquer código ≠ 123456 | Erro inline: "Código incorreto. Verifique e tente novamente." Campos limpam. |
| FRS3.2 | Código expirado | Digitar 000000 | Erro: "Código expirado. Solicite um novo código." Link de reenvio aparece imediatamente. |
| FRS3.3 | Menos de 6 dígitos | Tentar avançar com campos incompletos | Botão "Verificar" desabilitado |
| FRS3.4 | Máximo de tentativas (3x código errado) | Errar o código 3 vezes consecutivas | Bloqueio temporário: "Muitas tentativas. Aguarde X minutos para tentar novamente." ⚠️ Tempo de bloqueio a definir pelo time. |
| FRS3.5 | Usuário volta para etapa 2 | Pressionar voltar | Retorna para /recuperar-senha/canal; canal anterior mantido selecionado |

## Etapa RS4 — Nova Senha

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| RS4.1 | Usuário digita nova senha | Indicador de força atualiza em tempo real |
| RS4.2 | Senha com 8+ chars + letras + números | Indicador mostra "Forte" (verde) |
| RS4.3 | Usuário confirma a senha | Campo de confirmação sem erro |
| RS4.4 | Clica em "Salvar nova senha" | Toast "Senha alterada com sucesso!"; redireciona para /acesso após 1.5s |
| RS4.5 | Tela de login carrega | Toast: "Senha atualizada. Faça login para continuar." |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FRS4.1 | Senha com menos de 6 caracteres | Digitar senha curta | Botão desabilitado; indicador "Fraca" vermelho |
| FRS4.2 | Senhas não coincidem | Digitar senhas diferentes nos dois campos | Erro inline no campo 2: "As senhas não coincidem." |
| FRS4.3 | Senha igual à anterior | Digitar "senha123" | Erro: "A nova senha deve ser diferente da anterior." |
| FRS4.4 | Usuário tenta voltar da etapa 4 | Pressionar back do browser | Não permitir — sem botão voltar; back redireciona para /acesso |
| FRS4.5 | Erro ao salvar (API offline) | Simular falha de rede | Mensagem: "Não foi possível salvar sua senha. Tente novamente." Campos mantidos. |

## Forks Transversais

| ID | Cenário | Resultado esperado |
|----|---------|-------------------|
| FRST.1 | Perda de conexão em qualquer etapa | Mensagem de sem conexão; estado da etapa preservado |
| FRST.2 | Sessão do fluxo expirada (inatividade > 10min) | Redirecionar para /recuperar-senha com mensagem: "Sua sessão expirou. Comece novamente." |
| FRST.3 | Usuário já autenticado tenta acessar /recuperar-senha | Redirecionar para /painel |

## Checklist de Regressão (rodar a cada deploy)

- [ ] Happy Path completo: CPF → canal → OTP → nova senha → login
- [ ] CPF não cadastrado exibe erro correto (FRS1.3)
- [ ] Acesso direto a etapas intermediárias redireciona para etapa 1 (FRS1.5)
- [ ] Seleção de canal — apenas um ativo por vez (FRS2.3)
- [ ] Código incorreto limpa campos e exibe erro (FRS3.1)
- [ ] Código expirado exibe link de reenvio imediato (FRS3.2)
- [ ] Bloqueio após 3 tentativas erradas (FRS3.4)
- [ ] Senhas não coincidem bloqueia avanço (FRS4.2)
- [ ] Senha igual à anterior exibe erro (FRS4.3)
- [ ] Back na etapa 4 redireciona para /acesso (FRS4.4)
- [ ] Toast de confirmação aparece na tela de login após redefinição (RS4.5)
