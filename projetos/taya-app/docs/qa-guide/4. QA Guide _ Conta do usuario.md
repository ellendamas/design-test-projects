# QA Guide — Conta do Usuário
**seutudo. · Taya Tech · Confidencial**
Versão 1.0 — Maio 2026

---

## Visão Geral

A seção de Conta agrupa configurações pessoais, segurança, informações e saída do app. É acessada pela nav inferior (mobile) ou sidebar (desktop) através do item "Conta".

```
/minha-conta (índice)
├── /minha-conta/meus-dados
├── /minha-conta/editar-endereco
├── /minha-conta/dados-bancarios
└── /minha-conta/alterar-senha
```

Itens externos (abrem fora do app):
- Avaliar o aplicativo → Play Store / App Store
- Política de Privacidade → `https://seutudo.com.br/politica-de-privacidade`
- Termos de Uso → `https://seutudo.com.br/termos-de-uso`

Rota base: `/minha-conta`
Acesso: apenas usuários autenticados

---

## Como usar este guia

Cada seção cobre uma subtela. Para cada uma:
- **Caso de sucesso (Happy Path)**: comportamento esperado em condições normais
- **Casos alternativos (Forks)**: condições de exceção com comportamento esperado

## Tela Índice — `/minha-conta`

### Objetivo
Exibir perfil resumido e listar acesso às subtelas de conta.

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| MC.1 | Usuário acessa `/minha-conta` | Layout com foto no topo (mobile) ou coluna esquerda (desktop) |
| MC.2 | Nome do usuário exibido em uppercase | Ex: "ELLEN SOUZA" |
| MC.3 | CPF exibido mascarado por padrão | `SensitiveData` exibindo `•••.•••.•••-••` |
| MC.4 | Ícone de olho ao lado do CPF | Clicar alterna visibilidade do CPF |
| MC.5 | 4 grupos de menu visíveis | Conta, Segurança, Configurações, Políticas |
| MC.6 | Cada item navega para sua rota | Clique em "Meus dados" → `/minha-conta/meus-dados` |
| MC.7 | Itens externos com ícone `ArrowSquareOut` | "Avaliar o aplicativo", "Política de Privacidade", "Termos de Uso" |
| MC.8 | Botão "Sair" no rodapé | Texto laranja; clique limpa sessão e navega para splash |
| MC.9 | Versão do app no rodapé | "Versão 0.1.0-mvp" em texto muted |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FMC.1 | Usuário não autenticado | Acessar `/minha-conta` sem sessão | Redirecionar para `/acesso?redirect=/minha-conta` |
| FMC.2 | Toggle de privacidade global ativo | Ativar toggle na home antes de acessar Conta | CPF mascarado; toggle na tela de conta reflete o estado global |

## Meus Dados — `/minha-conta/meus-dados`

### Objetivo
Exibir informações pessoais do usuário. Campos vinculados ao contrato são somente leitura. E-mail e celular são editáveis.

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| MD.1 | Tela carregada | Header com botão voltar e `PrivacyToggle`; aviso sobre dados contratuais |
| MD.2 | CPF, RG e data de nascimento exibidos como `SensitiveData` | Mascarados por padrão; olho individual para cada campo |
| MD.3 | E-mail e celular em inputs editáveis | Campos com bordas, preenchidos com dados do cadastro |
| MD.4 | Usuário altera e-mail | Campo aceita novo valor |
| MD.5 | Usuário altera celular | Máscara `(00) 00000-0000` aplicada |
| MD.6 | Botão "Salvar alterações" ativo após mudança | Habilitado somente quando e-mail ou celular diferem do original |
| MD.7 | Usuário clica em "Salvar alterações" | Toast Sonner: "Dados atualizados."; navega para `/minha-conta` após 1,5s |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FMD.1 | E-mail editado para formato inválido | Digitar "emailsemaroba" | Validação ao tentar salvar; mensagem: "Informe um e-mail válido." |
| FMD.2 | Celular editado para número incompleto | Digitar menos de 10 dígitos | Botão desabilitado ou validação ao salvar |
| FMD.3 | E-mail alterado para um já cadastrado | Simular conflito de e-mail | Mensagem: "Este e-mail já está em uso." |
| FMD.4 | Nenhuma alteração feita | Não modificar nada | Botão "Salvar alterações" desabilitado |
| FMD.5 | Usuário clica em "Voltar" sem salvar | Clicar em botão voltar após editar | Navega para `/minha-conta`; alterações não salvas perdidas (sem confirmação por ora) |

## Editar Endereço — `/minha-conta/editar-endereco`

### Objetivo
Atualizar o endereço residencial do usuário com preenchimento automático via ViaCEP.

### Fluxo em 3 passos internos
```
Passo 1: Confirmação do endereço atual
→ Passo 2: Busca por CEP
→ Passo 3: Formulário completo
→ Tela de sucesso
```

### 1 — Confirmação do endereço atual

#### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| EA.1 | Tela exibe endereço atual em layout quebrado por linhas | Rua, número, bairro, cidade/UF, CEP |
| EA.2 | Usuário clica em "Confirmar endereço" | Salva endereço atual sem modificação; exibe tela de sucesso |
| EA.3 | Usuário clica em "Alterar endereço" | Avança para Passo 2 (busca por CEP) |

#### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FEA.1 | Usuário sem endereço cadastrado | Acessar sem endereço no perfil | Pular passo 1; ir direto para busca por CEP |

---

### 2 — Busca por CEP

#### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| EB.1 | Campo de CEP com máscara `00000-000` | Máscara aplicada ao digitar |
| EB.2 | Usuário digita 8 dígitos | App consulta `https://viacep.com.br/ws/{cep}/json/` automaticamente |
| EB.3 | Loading durante a consulta | Spinner no campo de CEP; campos abaixo com skeleton |
| EB.4 | CEP válido retornado | Campos logradouro, bairro, cidade, UF preenchidos automaticamente |
| EB.5 | Foco automático no campo "Número" | Cursor posicionado no número após preenchimento automático |

#### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FEB.1 | CEP inexistente | Digitar `99999-999` | Mensagem: "CEP não encontrado. Verifique e tente novamente." Campos permanecem em branco para preenchimento manual. |
| FEB.2 | CEP com menos de 8 dígitos | Digitar 7 números | Consulta não disparada; máscara indica dígitos faltantes |
| FEB.3 | API ViaCEP offline ou timeout | Simular falha de rede | Mensagem: "Não conseguimos buscar o endereço agora. Preencha manualmente." Campos desbloqueiam para edição. |
| FEB.4 | Link "Não sei meu CEP" | Clicar no link | Abre `https://buscacepinter.correios.com.br` em nova aba |

---

### 3 — Formulário completo

#### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| EC.1 | Campos preenchidos automaticamente | Logradouro, bairro, cidade, UF com dados do CEP |
| EC.2 | Usuário edita logradouro e bairro | Campos editáveis aceitam alteração |
| EC.3 | Cidade e UF somente leitura | Campos com opacidade reduzida; não editáveis |
| EC.4 | Usuário preenche número (obrigatório) | Campo aceita números e texto |
| EC.5 | Usuário preenche complemento (opcional) | Campo aceita entrada; pode ficar vazio |
| EC.6 | Botão "Confirmar endereço" ativo | Ativo quando número preenchido |
| EC.7 | Usuário confirma | Tela de sucesso exibida inline com CTA para `/minha-conta` |

#### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FEC.1 | Número não preenchido | Tentar avançar sem número | Validação bloqueia; campo obrigatório destacado |
| FEC.2 | Logradouro apagado manualmente | Limpar o campo | Validação ao confirmar: "Informe o logradouro." |

## Alterar Senha — `/minha-conta/alterar-senha`

### Objetivo
Permitir que o usuário troque sua senha de acesso numérica de 6 dígitos.

### Happy Path
| Passo | Ação | Resultado esperado |
|-------|------|--------------------|
| AS.1 | Tela carregada | Headline conversacional + 3 campos de senha + regras visíveis |
| AS.2 | Usuário digita senha atual (6 dígitos) | Campo `type="tel"` aceita entrada; foco não perde entre dígitos |
| AS.3 | Usuário digita nova senha (6 dígitos) | Campo aceita; toggle de visibilidade funciona |
| AS.4 | Usuário confirma nova senha | Campo deve coincidir com nova senha |
| AS.5 | Botão "Salvar nova senha" ativo | Ativo quando os 3 campos preenchidos e nova senha === confirmação |
| AS.6 | Usuário salva | Toast Sonner: "Senha alterada com sucesso."; navega para `/minha-conta` após 1,5s |

### Forks
| ID | Cenário | Como reproduzir | Resultado esperado |
|----|---------|-----------------|-------------------|
| FAS.1 | Senha atual incorreta | Digitar senha errada | Mensagem: "Senha atual incorreta. Tente novamente." (somente com validação de backend) |
| FAS.2 | Nova senha diferente da confirmação | Digitar senhas diferentes nos dois campos | Botão desabilitado; mensagem inline: "As senhas não coincidem." |
| FAS.3 | Nova senha igual à atual | Digitar a mesma senha | Mensagem de aviso: "A nova senha deve ser diferente da atual." (se validado) |
| FAS.4 | Campo de senha perde foco entre dígitos | Digitar número e verificar se o campo mantém foco | Foco deve permanecer no campo até completar 6 dígitos |
| FAS.5 | Senha com menos de 6 dígitos | Tentar salvar com campo incompleto | Botão desabilitado |
| FAS.6 | Input aceita letras | Digitar caractere alfabético | Campo rejeita; aceita apenas dígitos numéricos (`type="tel"`) |
